= lightweight-vk

== 简介

此项目来源于书籍《Vulkan 3D graphics Rendering Cookbook》，出版于2025年2月，是比较新的Vulkan渲染技术书籍，作者:
. Sergey Kosarevsky: 育碧前渲染主管，现Meta Vulkan开发主管，职业经历丰富
. Alexey Medvedev: Meta的AR技术主管，有多个游戏大厂的工作经历
. Viktor Latypov: C/C++ 3D图形，嵌入式，图形视觉开发，经验丰富

lightweight-vk fork了meta的igl框架，重构并用vulkan1.3实现了bindless

=== 项目情况

. 项目定位: 原型参考级项目，轻薄封装
. 使用python拉取三方库和示例资产
.. 优点
... python作为脚本相对简单，可复用
.. 缺点 
... 实际效果类似submodule或者fetch content,只需写好cmake其实可以搞定
... 直接依赖了大型资产库，没有按需下载, 没有vendoring, 占空间, 下载慢，构建慢, 且大量资产没有实际使用
... 不直接支持vscode，只能用vs

== 潜在参考点

== 整体架构

主要对象声明，涉及的参数，枚举等，都放在LVK.h中，对象的封装非常扁平直观，没有很深的封装嵌套，没有过度的访问控制，核心对象都继承自运行时确定的接口，接口用虚函数实现

用宏来负责平台，所用三方库的隔离，宏挺多，但好在扁平，基本只有一层，所以也算好读

优点是集中管理，直观，没有过度封装，缺点是职责过于集中，改动和维护都得动这个文件

目前在架构上，我感觉已经没太多可参考的点了,主要区别在于功能实现的完善度

我觉得此代码的设计理念在于精简，没有过度封装和设计，作为一个定位为lightweight的项目，我是比较认同的

但是其在窗口系统，平台差异在代码里大量用宏，影响阅读体验，但是胜在减少了额外的封装

== 核心调用流程

也没太多可借鉴的，属于渲染器标准流程代码，还是一堆宏用于区分不同的窗口系统和平台，封装很薄，直接，确实很light weight

shader代码写到了同一个cpp里，有glsl和slang

[plantuml]
....
User -> VulkanApp: create
VulkanApp -> LVK: initWindow()
LVK <-- VulkanApp: LVKWindow*
VulkanApp -> LVK: createVulkanContextWithSwapchain()
LVK -> VulkanContext: create
VulkanContext -> VulkanContext: pick device
VulkanContext -> VulkanContext: init device
VulkanContext -> VulkanSwapchain: create and init swapchain
VulkanApp <-- VulkanContext: initialized VulkanContext
User -> VulkanApp: get Context
User <-- VulkanContext: Context*
User -> User: operate vulkan stuff
User -> VulkanApp: run()
loop per-frame
    VulkanApp -> VulkanApp: poll window events
    VulkanApp -> VulkanApp: drawFrame(), execute user recorded commands
    VulkanApp -> VulkanContext: submit(buffer, swapchain image)
end
User <-- VulkanApp: ~VulkanApp()
