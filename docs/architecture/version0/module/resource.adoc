= 资源管理模块

对应resource/目录

== 职责

. 资源指的是运行时资源，与资产作出区分，资源管理由resource manager负责，资产管理由asset manager负责
. 整个引擎的运行时资源缓存中心，负责资源缓存以便复用，负责资源生命周期管理，追踪，负责关联的GPU资源
. 同时负责资源对应GPU侧资源的生命周期
. 但是不负责材质系统，管线相关的资源
. 不负责场景图相关数据
. 不碰文件加载，只管理运行时资源
. 不做资产预处理，只管理处理成内部格式的数据

== 设计思路

=== resource的种类及实现方式

. 有两种资源类型
.. 基础类型: 不可拆分的最小单位类型，比如：单个纹理，单个buffer, 没有互相依赖的关系
.. 复合类型: 可拆分，但是一般看作一个整体的类型，比如：网格资源

* 复合类型应该由基础类型组成，复合类型引用基础类型，同时复合类型可以引用其他复合类型
* 每种类型都应该有引用计数，当有其他类型依赖时，计数加1，引用由句柄实现
* 复合类型之间可以交叉引用基础类型，基础类型不能有依赖，只能被依赖
** 复合类型可以引用其他复合类型
** 依赖链不能成环

. 本版应该有的基础类型:
+
* texture: 内部含有 rhi texture handle, 纹理相关属性如宽高等
* buffer: gpu中的一块内存，和相关属性比如用途，大小，rhi handle等
+
. 复合类型
+
* mesh: 引用buffer资源，如vertex buffer, index buffer等, 子网格包含在mesh中，记录对应buffer的偏移值，跨度， buffer可在不同mesh之间共享，用handle引用
* prefab(预制件)类型，如gltf, gltf看作预制件的一种， 可能包含: mesh, texture, 其中material通过材质系统关联，material是一个material handle
+
. 不包含的类型
+
* shader module, descriptor set, pipeline, xxx layout, 这些资源放在材质系统
* scene node, scene graph, 这些在场景系统中维护

=== gpu资源如何处理

=== 如何操作资源？包括创建，如何销毁

. 资源的真正卸载取决于引用计数,每个资源节点都有引用计数， 外部不能直接销毁资源，只能请求gc(), 由resource manager最终负责

=== 交叉引用方案

. 通过ref引用，拷贝会增加引用计数，或者通过resource manager显式增加计数，移动不会增加计数
. 加载、卸载行为不会导致计数变化
. resource实例是唯一的，但是多个handle可对应同一个resource，resource的嵌套包含通过resource的ref对应，不能resource套resource
. 引用计数在resource manager处统一管理，resource或者ref, handle没有引用计数数据

=== 如何存储

. resource在rm只有一份数据，外部多个handle可对应同一个resource
. 拷贝handle不会复制resource或者增加引用计数
. rm的handle是带类型的，方便区分不同类型的资源
. 为了避免ABA问题，及预留未来热重载扩展性，handle带分代信息，表示版本号
. handle的生成，包括id分发由RM负责
. 存储按照tag类型分不同的池存储

=== 如何判重

. 通过asset id和变体id判重，变体id默认为0，变体id用于实现同一个资产多个resource
. 如果不是资产创建的资源，有运行时id判断判重

=== 如何使用

. 引擎所有运行时资源都通过resource manager管理，外部不可自行持有或管理资源，而是通过handle/ref访问
. rm能追踪资源状态，能够管理和分发handle
. 支持多线程异步，异步任务分派给job system执行
. 资源系统只依赖backend以便调度GPU资源，GPU侧资源会与运行时资源对应，关系是n对n

=== 失败回退

. 注册时中途失败，整个资源引用计数不会更新，可以在gc()时被清理，会返回一个错误信息
. 加载时失败目前会报错，报错如何处理取决于调用方

== 本版边界

. 暂不实现流式加载，热重载, 但是设计上预留空间，比如分代handle,资源带状态，resource类型和标签隔离能力等
. 暂不支持多线程
. 暂不集成内存分配器，job system
. buffer目前是被mesh独占，不是共用的，但是架构上支持共用，未来可以优化

== 类设计

此处只展示核心类的核心成员，详见代码

[plantuml]
----
class Resource {
    资源保持唯一，基类
    此处有必要接口和实现分离，接口还带有AOP能力，可同时执行逻辑，方便跟踪资源状态，执行统一命令，存储公共数据
    ==
    + void load()
    + void unload()
    ==
    # virtual void doLoad()
    # virtual void doUnload()
    ==

    - uint32_t mAssetId
    - string mName
    - ResourceStatus mStatus
}
class BufferResource extends Resource {
    buffer 属于基础资源，其可以单独存在，也可以被其他复合类型的资源包含
    通过handle表示关联关系
    ==
    Hw开头代表RHI资源句柄
    - HwBufferHandle mBufferHandle;
}
class TextureResource extends Resource {
    texture也属于基础资源
    ==
    - HwTextureHandle mTextureHandle
}
class SubMesh {
    + uint32_t firstIndex
    + uint32_t indexCount
    + int32_t baseVertex
    + uint32_t materialSlot
}
class MeshResource extends Resource {
    复合资源
    ==
    - ResourceRef<BufferResource> mVertexBuffer
    - ResourceRef<BufferResource> mIndexBuffer
}

class PrefabResource extends Resource {
    复合资源
    ==
    - vector<ResourceRef<MeshResource>> mMeshes
}
class ResourceEntry {
    ResourceHandle handle
    uint32_t refCount
}

class ResourceManager {
    包含判重和资源记录
    包含各种资源的存储结构
    基础和复合资源的计数是分开的，复合资源会同时更新包含的基础资源的计数
    Tag用于支持同种资源根据用途和生命周期特征不同分开管理
    Tag分为对内Tag和对外Tag，是一对多的关系
    ==
    具体成员详见代码
    ==
    - unordered_map<ResourceKey, ResourceEntry<T>> mRegistry
    - Pool<ResourceType> mXxxPool;
    ...
}

ResourceManager *-- BufferResource
ResourceManager *-- TextureResource
ResourceManager *-- MeshResource
ResourceManager *-- PrefabResource
MeshResource *-- SubMesh
ResourceManager *-- ResourceEntry

== 核心调用链梳理

以复合资产(prefab为例)

[plantuml]
....
actor developer as User
activate ResourceManager
group 复合资产注册
     User -> ResourceManager: registerResource(T* asset)
     ResourceManager -> ResourceManager: 判重
     ResourceManager -> PrefabResource++: 构造 PrefabResource
     ResourceManager -> MeshResource++: 构造 PrefabResource的mesh resources
     ResourceManager -> BufferResource++: 构造 MeshResource的buffer resources
     ResourceManager -> TextureResource++: 构造 PrefabResource的texture resources
     ResourceManager <-- PrefabResource: 构造完成
     ResourceManager -> ResourceManager: 存储resources，  更新注册表, 更新计数
     User <-- ResourceManager: 返回prefab resource Handle
end
group 资源加载(prefab(gltf))
    User -> ResourceManager: load()
    ResourceManager -> PrefabResource: load(), PrefabResource status: [unload] to [loading]
    PrefabResource -> PrefabResource: doLoad()
    loop meshes
        PrefabResource -> MeshResource: load(), MeshResource status: [unload] to [loading]
        loop vertex/index buffers
            MeshResource -> BufferResource: load(), BufferResource status: [unload] to [loading]
            BufferResource -> BufferResource: create rhi buffer
            MeshResource <-- BufferResource: created buffer, BufferResource status: [loading] to [loaded]
            MeshResource -> BufferResource: writeBuffer(), upload mesh data
            MeshResource <-- BufferResource: uploaded, MeshResource status: [loading] to [loaded]
        end
    end
    loop textures
        PrefabResource -> TextureResource: load(), TextureResource status: [unload] to [loading]
        TextureResource -> TextureResource: create rhi texture
        PrefabResource <-- TextureResource: texture created, TextureResource status: [loading] to [loaded]
    end
    PrefabResource <-- PrefabResource: sub resources loaded, PrefabResource status: [loading] to [loaded]
    ResourceManager <-- PrefabResource: loaded
    User <-- ResourceManager: loaded
end
group 资源卸载
    User -> ResourceManager: load()
    ...与加载过程流程一致，只是逆向迭代unload， 不会改变计数, 当前版本buffer会被清空，可以unload()后重新load()...
    User <-- ResourceManager: unloaded
end
group 资源销毁
    ResourceManager -> ResourceManager: gc()
    loop 注册表资源(1. prefab resource)
        ResourceManager -> PrefabResource: 找到ref为0的prefab handle
        ResourceManager -> PrefabResource: unload() 不向下递归
        PrefabResource -> MeshResource: 计数-1
        ResourceManager <-- PrefabResource--: prefab从pool里清除，析构
    end
    loop 注册表资源(2, mesh resource)
        ResourceManager -> MeshResource: 找到ref为0的mesh handle
        ResourceManager -> MeshResource: unload()
        loop vertex/index buffers
            MeshResource -> BufferResource--: 计数-1
        end
        ResourceManager <-- MeshResource: mesh从pool里清除，析构
    end
    loop 注册表资源(3, texture resource)
        ResourceManager -> TextureResource: 找到ref为0的texture handle
        ResourceManager -> TextureResource: unload()
        ResourceManager <-- TextureResource--: mesh从pool里清除，析构
    end
    loop 注册表资源(4, buffer resource)
        ResourceManager -> BufferResource: 找到ref为0的buffer handle
        ResourceManager -> BufferResource: unload()
        ResourceManager <-- BufferResource--: buffer从pool里清除，析构
    end
end
group 全局销毁
    ResourceManager -> ResourceManager: clearAll()
    ...与销毁相似，先prefab unload,再mesh,再texture,再buffer只是不管refCount...
    ResourceManager -> ResourceManager--: 清空注册表
end
....
